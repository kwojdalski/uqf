# Functions the suite never enters, and why that is accepted for now.
#
# tests/q/run_coverage.q compares the whole-suite run against this list and
# FAILS when they disagree, in either direction:
#
#   a function never entered that is NOT listed   a new blind spot
#   a listed function that IS now entered         the list has gone stale
#
# Both are failures on purpose. A baseline that only ratchets one way rots:
# entries stay after the gap they described is closed, the list stops
# describing anything, and the next reader cannot tell which lines are still
# true. Removing a line is the cheaper half of closing a coverage gap.
#
# A name here is a statement that nothing in the suite CALLS the function -
# not that it is untestable, and not that it is unimportant. Several of these
# should simply be covered; they are listed because they are not, not because
# they should not be.
#
# Blank lines and lines starting with # are ignored.

# --- Needs a running TorQ process --------------------------------------
# .qtorq is the TorQ block library and .qpipe.job the subscriber processes. Both
# assume a tickerplant, a publish handle and a timer; the transforms they
# call are tested through .qetl.transform instead, which is the part that computes.
# publish and as_table are not here: the handle is a seam, and
# test_stream_job.q hands them a recording one.
#
# wait_for_tickerplant and reload_hdb joined this list in #462, and the four
# that arrived with them did NOT: elapsed_ms, record_received, apply_verbose
# and record_published need no tickerplant at all and are covered by
# test_torq_pipeline.q instead. This list means "uncovered on purpose", so
# the distinction is the whole value of it - a pure millisecond conversion
# sitting here would be a lie that got cheaper to repeat.
#
# These two earn their place: wait_for_tickerplant BLOCKS until a plant
# answers (startupdepcycles with check_cycles 0W waits forever), so a test
# that entered it would hang the suite rather than fail it; reload_hdb opens
# discovered handles and is already listed in .qt.man.examples.needs_live for the
# same reason.
.qtorq.connect_etl

.qtorq.load_uqf
.qtorq.safe_timer
.qtorq.subscribe_etl
.qtorq.subscribe_tables

#

# be in this block is covered now, and how says something about baselines.
#
# Eighteen `.qpipe.job` names sat here under the heading that these two workers
# reach "a real database, a real ODBC driver". They do not. A source takes the

# survived long enough to read as settled.
#

# test_worker_runtime.q: `.qetl.job.bounded.delegate` reads its parameter names off the
